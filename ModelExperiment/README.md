# ModelExperiment

Offline evaluation and fine-tuning pipeline for Recall's parking sign recognition.

Covers two approaches:
1. **Heuristic baseline** — Python port of `VisionAnalyzer` logic, hand-written regex over raw OCR tokens
2. **Fine-tuned T5** — `flan-t5-small` trained to map raw OCR tokens → correct parking label

---

## Results

Evaluated on 82 real parking images captured in UAE (mainly Dubai) malls and car parks.

| Metric | Heuristic baseline | Fine-tuned T5 |
|---|---|---|
| Exact match | 28.0% (23/82) | **59.8% (49/82)** |
| Token F1 | 0.661 | **0.862** |

### Why the heuristic fails

| Failure mode | Heuristic | Model |
|---|---|---|
| Suffix stripping — reads `P1`, misses row letter | ❌ `P1` | ✅ `P1 H` |
| Noise pollution — car plate bleeds into label | ❌ `YOU HAVE PARKED` | ✅ `B5` |
| Floor prefix dropped | ❌ `G23` | ✅ `P2 G23` |
| Numeric spot misread with row prefix | ❌ `A 12` | ✅ `12` |
| Empty OCR (8 images) | ❌ defaults to `Memory` | ❌ defaults to `Memory` |

## How it works

```
VNRecognizeTextRequest
        │
        │  raw tokens + bounding-box normalized heights
        ▼
  Format as  TEXT(size) pairs, joined by " | "
  e.g.  "P1(0.042) | H(0.031) | LEVEL 3(0.012) | 32449(0.008)"
        │
        ▼
  flan-t5-small  (input: "parking ocr: P1(0.042) | H(0.031) | ...")
        │
        │  predicts suffix only, e.g. "P1 H"
        ▼
  postprocess_suffix()
        │  anchors prediction back to actual OCR tokens
        │  catches hallucinations, fixes I-prefix / P-prefix drops
        ▼
  format_full_label()  →  "Parking · P1 H"
```

**Key insight:** bounding-box font size is a strong signal. The actual spot identifier is almost always the largest text in the frame. Passing size as part of the token string lets T5 learn this implicitly without any architectural changes.

## Layout

| Path | Purpose |
|---|---|
| `parking_baseline/baseline_eval.py` | Runs OCR + heuristic, writes CSV + report |
| `parking_baseline/labels.csv` | Ground truth (`image_id`, `true_label`) |
| `parking_baseline/baseline_results.csv` | Latest run output (regenerated by script) |
| `parking_baseline/baseline_report.txt` | Human-readable summary from last run |
| `recall_eval.ipynb` | Baseline analysis and ad-hoc eval |
| `recall_finetune_v1.ipynb` | First fine-tuning run (heuristic vs T5, Colab) |
| `recall_finetune_v2.ipynb` | v2 — synthetic examples, improved postprocessing |
| `model/recall_parking_model/` | Saved flan-t5-small checkpoint (gitignored) |

Images (`park_*.jpg`) are **gitignored** — add them locally next to `labels.csv` when running eval.

## Run baseline eval

Install deps once from `ModelExperiment/`:

```bash
cd ModelExperiment
pip install -r requirements.txt
```

From `parking_baseline/` (Tesseract must be installed and on `PATH`):

```bash
cd parking_baseline
python baseline_eval.py --images . --labels labels.csv
```

## Run fine-tuning (Colab)

The fine-tuning notebooks are designed for Google Colab (free T4 GPU, ~15 min per run).

1. Upload `recall_finetune_v2.ipynb` to Colab
2. Mount Google Drive and place `vision_log.json` and `labels.csv` at:
   ```
   MyDrive/Recall_Parking/vision_log.json
   MyDrive/Recall_Parking/labels.csv
   ```
3. Run all cells — training stops automatically via early stopping (patience=5)
4. Download `recall_parking_model/` from the Colab file browser

To convert the saved checkpoint to CoreML for on-device inference, see Apple's
[`coremltools` docs](https://coremltools.readme.io/docs/pytorch-conversion).

## Training details

| Setting | Value |
|---|---|
| Base model | `google/flan-t5-small` |
| Optimizer | AdamW, lr=1e-4, weight_decay=0.05 |
| Scheduler | Linear warmup (10% of steps) |
| Max epochs | 30 (early stopping, patience=5) |
| Batch size | 8 |
| Input format | `parking ocr: TOKEN(size) \| TOKEN(size) \| ...` |
| Target format | suffix only, e.g. `P1 H` (not full label) |
| Max input tokens | 96 |
| Max output tokens | 16 |
| Real training examples | 45 images, 70/15/15 split |
| Augmentation | 8 variants per training example (dropout, shuffle, char corruption, noise injection) |
| Synthetic examples | 16 hand-crafted examples for known hard patterns |

Augmentation-generated examples are kept strictly within the training fold — val and test sets contain only unmodified originals.

## What's next

- [ ] **Constrained decoding** — build a trie from the label vocabulary and use `prefix_allowed_tokens_fn` in `.generate()` to eliminate hallucinations like `333` or `P1 D` for clearly numeric spots
- [ ] **Confidence-based fallback** — use beam scores (`output_scores=True`) to defer to the heuristic when the model is uncertain; the heuristic still wins on some cases
- [ ] **More labeled data** — the 7 `Parking · I` failures all appear to be the same garage; 5–10 more labeled examples from that environment would likely fix them
- [ ] **License plate recognition** — extend the pipeline to UAE plate formats (white/silver plates, Arabic + Latin characters) for entry/exit logging use cases
- [ ] **CoreML export** — quantize and convert for fully on-device inference; no network call needed at capture time
